# docmost-teams v0.96.0

The first docmost-teams release that mirrors an upstream Docmost release, and
the first that contains no Docmost Enterprise-licensed code. It rebases
docmost-teams onto Docmost
[v0.96.0](https://github.com/docmost/docmost/releases/tag/v0.96.0) (previously
v0.95.0).

## From upstream Docmost v0.96.0

- Public spaces (beta): publish a whole space as public docs, with an optional
  `/docs` directory. Off by default; requires `BETA_PUBLIC_SPACES=true` and a
  workspace opt-in.
- Search: jump to search, enhanced search filters, and searching group members.
- Editor: footnotes, a lightbox for images and media, automatic RTL text
  direction, gap cursors between top-level blocks, and many smaller fixes.
- Pages: compare two page versions, a page attachments modal, and a fix for
  printing public pages.
- Collaboration upgraded to Hocuspocus v4, and a WebSocket relay fix.
- Redis URL parsing now supports ACL usernames, encoded credentials, empty
  passwords, missing ports, and TLS.
- The client is code-split and lazy-loaded.

## New in this release

- **No Enterprise code.** Upstream's Enterprise-licensed client code
  (`apps/client/src/ee`), `packages/ee` and `packages/base-formula` are gone,
  and the fork's client screens were rewritten from a clean-room
  specification. CI fails if Enterprise code comes back.
- **SSO presets.** Keycloak, Google, Microsoft Entra ID, Facebook and generic
  OpenID Connect, each with a guided form, the callback URL shown before
  saving, and a **Test connection** button.
- **Group and role sync** follows nested claims and wildcard filters, and
  only takes back what the provider granted: memberships and roles assigned
  in Docmost are never removed.
- **Safer SSO administration.**
  - Only workspace owners can add, change, test or delete providers; admins
    see them read-only.
  - A saved client secret is only sent to the issuer it was saved for;
    pointing a provider at a new issuer requires entering the secret again.
  - The last enabled provider can't be disabled or deleted while SSO is
    enforced.
  - New providers map no identity-provider groups to workspace roles until an
    owner adds them.
  - Changing your email in Docmost marks it unverified. If an SSO sign-in
    then matches that account, it takes the account over: other sessions
    end and the password is replaced. This stops someone from claiming a
    colleague's address before the colleague first signs in with SSO.
- **Owner access** now also covers the real-time editor, live page-tree
  updates and notifications, so owners can edit pages in spaces they aren't a
  member of.
- **Private spaces** get a Home tab for their pages, shown once you have one.
  They can't be published as public spaces: anonymous public-space routes and
  listings treat them as unpublished, and converting a space to private also
  unpublishes it. Moving a page into a private space removes its public share,
  and share search no longer answers for shares whose space doesn't allow
  sharing. Converting a space to private makes its member a space admin.
- Releases mirror upstream Docmost versions, and CI runs before any image is
  published.

## Upgrade notes

- **Replace older images.** Images published before this release contained
  Enterprise-licensed client code.
- **SSO administration moves to owners.** Admins who managed SSO providers
  need a workspace owner to make changes from now on.
- **Existing OIDC providers with group sync keep their `Root` → owner rule**,
  now stored as an owner group you can see and change in the provider form.
  If you're coming from upstream Docmost rather than an earlier docmost-teams
  build, check that setting: `Root` members become owners while it's there.
  New providers start with no owner or admin groups.
- **Features from upstream's Enterprise Edition aren't available**: AI, API
  keys, audit logs, MFA, SCIM, templates, page verification and page-level
  permissions, comment resolution, PDF export, and database pages. Their
  screens say they aren't part of docmost-teams.
- The container image now runs on Node 26, as upstream does.
- Database migrations run automatically on startup: upstream's
  `page-title-trgm-index`, `oauth`, `siem-destinations` and `public-spaces`,
  and the fork's `sso-sync-provenance` and `sso-explicit-owner-groups`. The
  trigram index can take a while on large `pages` tables.
- `.env.example` no longer contains a usable `APP_SECRET`. Set your own; for
  local development, `script/bootstrap-local-dev.sh` generates one.
- `docker-compose.yml` uses `ghcr.io/mesudip/docmost-teams:latest`.
- Back up the database before upgrading.
